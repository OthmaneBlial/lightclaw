# LightClaw Support

LightClaw is an early-stage, self-hosted project maintained on a best-effort basis.

## Choose the right channel

| Need | Channel |
|---|---|
| Install, configuration, or usage question | [GitHub Discussions Q&A](https://github.com/OthmaneBlial/lightclaw/discussions/categories/q-a) |
| Explore an idea before implementation | [GitHub Discussions Ideas](https://github.com/OthmaneBlial/lightclaw/discussions/categories/ideas) |
| Reproducible product defect | [Bug form](https://github.com/OthmaneBlial/lightclaw/issues/new?template=bug.yml) |
| Official provider contract mismatch | [Provider form](https://github.com/OthmaneBlial/lightclaw/issues/new?template=provider.yml) |
| Sanitized, reproducible workflow | [Showcase form](https://github.com/OthmaneBlial/lightclaw/issues/new?template=showcase.yml) |
| Suspected vulnerability | [Private vulnerability reporting](https://github.com/OthmaneBlial/lightclaw/security/advisories/new) |

Do not share bot tokens, API keys, private prompts, raw receipts, repository contents,
usernames, or local paths. Replace them with synthetic values before posting.

## What makes a support question answerable

Run `lightclaw doctor --json`, inspect the output, and share only the redacted fields that
are relevant. Include the LightClaw commit/version, operating system, Python version,
installation method, expected behavior, and smallest reproduction. Live provider or
Telegram credentials are never required to reproduce the deterministic demo.

Feature deadlines, private consulting, and guaranteed response times are not offered.
Actionable security reports follow the response targets in [SECURITY.md](SECURITY.md).
