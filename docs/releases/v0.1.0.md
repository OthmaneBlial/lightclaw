# LightClaw v0.1.0

> **DRAFT — not released.** Publish only after the private-alpha aggregate, PyPI Trusted
> Publisher, required checks, and release checklist are verified.

LightClaw turns a bounded Telegram request into reviewed, verified work on local projects.
This first alpha release emphasizes fail-closed access, explicit approval, local evidence,
reviewable patches, deterministic demos, and honest trust boundaries.

## Install

After publication, install the distinct distribution into an isolated environment:

```bash
pipx install lightclaw-ai==0.1.0
# or
uv tool install lightclaw-ai==0.1.0
```

The installed command is `lightclaw`. No `curl | sh`, root install, Telegram token, or model
credential is required for the deterministic demo.

## Verify

Run the token-free repository story and the redacted diagnostic:

```bash
lightclaw demo --scenario repo-task --output ./lightclaw-demo --json
lightclaw doctor --json
```

The demo must finish with an accepted local receipt, a real patch, and passing fixture test
output. It proves the recorded request-to-review path; it does not prove live Telegram or
provider quality.

## Upgrade

This is the first stable tag. Users of a Git checkout should back up
`~/.config/lightclaw/` and `~/.lightclaw/`, uninstall the checkout-managed tool, then install
`lightclaw-ai==0.1.0`. Future `0.x` migrations follow [UPGRADING.md](../UPGRADING.md) and
will name every manual setting or data step.

## Uninstall

For an isolated package install:

```bash
pipx uninstall lightclaw-ai
# or
uv tool uninstall lightclaw-ai
```

Configuration and runtime data remain by default. Review and back up anything needed before
removing `~/.config/lightclaw/` or `~/.lightclaw/` manually. Compatibility-installer users
can preview with `lightclaw uninstall --dry-run` before `--apply`.

## Compatibility

- Python 3.10–3.13 on supported Ubuntu/Linux and macOS runners.
- Telegram is the supported remote control surface; terminal fixture mode is for local
  verification.
- OpenAI/xAI, Anthropic, Gemini, DeepSeek, and Z-AI routes share one bounded provider
  contract; real availability and billing remain provider responsibilities.
- The optional container is Linux-based and runs as an unprivileged user.

## Security boundaries

- LightClaw keeps configuration, memory, receipts, task workspaces, and raw alpha evidence
  local and private by default.
- Telegram access requires an explicit numeric allowlist; public mode fails closed unless a
  separate acknowledgement is present.
- High-risk operations require explicit confirmation, while delegated workers receive a
  minimal environment and bounded capability profile.
- Context sent to a hosted provider leaves the local trust boundary. LightClaw cannot make
  a third-party API local or private.
- Sanitized Run Cards and alpha aggregates are opt-in exports; raw receipts are never
  public showcase material.

## Known limitations

- This is alpha software, not an autonomous production operator or security sandbox.
- Default memory retrieval is bounded lexical SQLite FTS5, not semantic understanding.
- Deterministic adapters and fixtures do not measure live model reasoning or Telegram
  delivery quality.
- Real private-alpha results, package/container URLs, digests, attestations, and community
  showcase evidence remain release gates while this file is a draft.
- External CLIs, provider SDKs, host permissions, and user repositories remain separate
  trust and failure boundaries.

## Artifacts and provenance

The completed GitHub Release must attach the wheel, source distribution, and machine-readable
runtime footprint produced by the release workflow. GitHub build provenance must cover the
distributions, PyPI must show Trusted Publishing attestations, and GHCR must expose immutable
`v0.1.0` and `latest` digests built from the release commit.

## Rollback

Before upgrading or connecting real work, back up the private config/runtime directories.
To roll back application code, uninstall the package and reinstall the last verified tag;
for this first release that reference is `v0.1.0`. Restore the matching backup only when
release notes document a data migration, then run `lightclaw doctor --json`.

`lightclaw undo` is narrower: it can revert one LightClaw-owned task workspace after a dry
run. It is not an application-version rollback and refuses arbitrary paths, symlinks, and
unregistered user directories.
